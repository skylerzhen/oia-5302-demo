## 要回答的问题

评标会上，我们能否用一场可复现的现场演示，证明已提交方案对 RFQ 五个模型的核心承诺（可确认的解析、带证据的匹配、动态双语 avatar 面试、可解释评分、人工终审、离线运行）真实存在——而非仅存在于文档？

## Goal

存在一场 **22–28 分钟、9 个场景（S0–S8）、在物理断开外网的本地环境上连续跑完**的演示：

> 一名候选人向 OIA 一个**金融类岗位**（非技术岗，从而 live coding 合法出界）投递简历 → 解析确认建档 → 匹配排序入围 → 简短测评 → 阿英双语 avatar 面试（动态追问）→ 评分与建议 → 招聘官人工终审，全程审计留痕。

每个场景对应下表中至少一条 RFQ 条款或澄清回复；全部 10 条 Gate 于 **8/16 内部验收会**判定通过；8/17（周一）可向 UIS/OIA 交付。演示两次彩排结果一致（同输入同流程，第二次录像留档）。

**明确不做（每条有依据）：**
- live coding 现场演示——demo 岗位选定为**非技术岗**，RFQ 原文 live coding 仅限 "for technical roles"
- 情绪/人格识别标签——已提交方案承诺形态是行为化响应，非情绪标签
- 写实生成式口型——已提交方案中为可选路径，非基础承诺
- Jadarah 真实对接——无沙箱环境；S1/S8 的写回动作用**明确标注 "simulated endpoint"** 的模拟端点演示，不冒充真集成
- 屏幕出现任何未实测性能数字（延迟/WER/准确率 SLA）
- 深度监考、10 路并发、故障切换——超出 demo 目的
- 真实候选人数据——全合成
